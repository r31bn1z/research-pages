# research-pages

外出中に Codex / Cursor / Claude などへ調査を依頼し、結果を GitHub Pages で読むための、ビルド不要の静的サイトです。
GitHub Pages は `docs/` をそのまま公開します。

## 調査から閲覧まで

1. エージェントへ、下の「依頼テンプレート」を使って調査を依頼する。
2. エージェントは一次情報を優先して調査し、`DESIGN.md` に沿った HTML レポートを作る。
3. レポートを `docs/reports/YYYY-MM-DD-topic.html` として保存し、`docs/index.html` の一覧へ追加する。
4. リンク、HTML、表示を確認してコミットし、Pull Request を作る。
5. Pull Request をマージする。GitHub Pages のデプロイ完了後、トップページから読む。

クラウド上のエージェントに 1〜4 をまとめて任せて構いません。この README と `DESIGN.md` を「成果物の契約」とし、調査テーマ固有の指示だけを毎回追加する運用を想定しています。公開リポジトリに置けない情報や認証情報は、依頼にも成果物にも含めないでください。

### 依頼テンプレート

```text
「（調査テーマ）」を調査し、このリポジトリの README.md の規約に従って
GitHub Pages 用レポートを作成してください。

知りたいこと:
- （質問1）
- （質問2）

条件:
- 想定読者: （例: 技術者ではない自分）
- 基準日: YYYY-MM-DD
- 重視する点: （例: 費用、実現性、リスク）
- 除外するもの: （任意）

docs/reports/YYYY-MM-DD-topic.html に保存し、docs/index.html に追加してください。
出典のリンクと参照日を明記し、事実・推測・提案を区別してください。
レポートの構成や見た目は内容に合わせ、DESIGN.md に従ってください。
表示とリンクを確認して、変更をコミットし Pull Request を作成してください。
```

## ファイル構成

```text
docs/
├── index.html          # 公開トップ。新しいレポートを上に追加
├── assets/
│   └── style.css       # トップページのスタイル
└── reports/
    └── YYYY-MM-DD-topic.html
```

ファイル名の `topic` は、短い英小文字の kebab-case にします。

## レポートの規約

制約は意図的に緩くしています。

- 成果物はブラウザで直接開ける HTML にする。
- モバイルでも PC でも読みやすくする。
- [`DESIGN.md`](DESIGN.md) の方針に沿う。

固定テンプレート、決められた章立て、共通 CSS の使用は求めません。調査対象に合う表現を選んでください。なお、内容の信頼性のため、事実には可能な限り一次情報へのリンクと参照日を添え、推測や提案とは区別します。

## 公開前チェック

最低限、次を確認します。

```bash
# HTML ファイルとローカル参照の簡易チェック
python3 scripts/check_site.py

# ローカル表示（http://localhost:8000/）
python3 -m http.server 8000 --directory docs
```

調査内容は時間とともに古くなります。重要な判断に使う場合は、レポートの基準日とリンク先の最新情報を再確認してください。
